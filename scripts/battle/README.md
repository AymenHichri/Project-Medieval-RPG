# scripts/battle — battle rules (no nodes)

Pure `RefCounted` logic. Nothing here awaits, touches the scene tree or names an autoload.
Every random roll goes through the `RandomNumberGenerator` passed to `BattleEngine.setup()`, so
the same seed always gives the same battle.

| File | Role |
|---|---|
| `battle_engine.gd` | Round loop: `setup` → `begin_round` → `execute_next`… → `end_round`; `outcome`, `compute_rewards` |
| `action_resolver.gd` | One `BattleAction` → `Array[BattleEvent]`: targeting/retargeting, MP, items, flee |
| `damage_calculator.gd` | Formulas and their named constants (§6.3 of the plan) |
| `status_effects.gd` | Apply, refresh, immunity, round-end ticks, skip-turn rule |
| `turn_order.gd` | Flee > Defend > agility × spread, stable ties |
| `enemy_ai.gd` | `AIProfile` → action |
| `combatant.gd`, `active_status.gd` | Live state wrapping the read-only data Resources |
| `battle_action.gd`, `battle_event.gd` | Input and output of the engine; event payload keys are listed on `BattleEvent.Type` |
| `battle_setup.gd`, `battle_result.gd` | Hand-off from and to the world (`SceneManager`) |
| `encounter_roller.gd` | Random encounters: `should_trigger` (grace + chance × multiplier), `pick_group` (flags, weights), `make_setup` |

Data Resources live in `scripts/resources/`; the `.tres` files in `res://data/` are generated by
`tools/build_battle_data.gd` (encounter tables in `data/encounters/`: `tools/build_encounters.gd`). Tests share builders from `tests/battle_fixtures.gd`.

The presentation that plays these events (sprites, menus, HUD) lives in `scenes/battle/` (see its README).
